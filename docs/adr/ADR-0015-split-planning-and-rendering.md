# ADR-0015 企画（produce-video）と生成（render-media）をスキルとして分ける

## Context

[ADR-0009](ADR-0009-sonagi-stops-at-definitions.md) は「スキルは定義とプロンプトまでを出し、
画像・音声・動画の実体を生成しない」と決めた。理由は決定性・検証可能性・環境非依存であり、
その判断自体は実運用でも正しく働いた——企画側は最後まで純粋関数のまま検査を通り続けた。

しかし実際に1本作ってみると、**実体化を誰かがやらねばならない**ことがはっきりした。
そしてホスト側にレンダラーを書いた時点で、次の要求が出た:
**生成の工程を他の媒体（ポッドキャスト、スライド）や他のサービスにも応用したい。**

このとき、生成の手順（画像 → 音声 → 実測で再計時 → 効果音/BGM → 動画 → 結合）や、
「在るものは作り直さない」「音に画を合わせる」「生成物を実測してから完了と言う」といった規律は、
**媒体にもサービスにも依存していない**。依存しているのはエンドポイントとモデルIDだけである。

つまり生成には、**型として共有できる部分**と**ホストに閉じるべき部分**が混在していた。

## Decision

**企画と生成を別のスキルに分ける。**

- **`produce-video`（企画）** … 定義まで。純粋関数性を保つ。ADR-0009 の核はここに残る
- **`render-media`（生成）** … 定義を実体にする。外部サービスを叩き、課金が発生する

**そして生成側を、型とアダプタの2層に切る。**

- **ハーネス（`rules/render-media/`）** … 工程の順序と依存、アダプタの契約、
  実測で再計時する作法、「200 は作れたではない」という規律
- **ホスト（`tools/render/`）** … ElevenLabs 固有の実装。エンドポイント、モデルID、
  サービスの癖の吸収（クリップ長が 4/6/8 秒しか取れない、画像 API にネガティブプロンプトが無い）

**生成する主体と検証する主体を分ける。** `media-checker` が実体を開き、
長さ・寸法・比率・画像に文字が焼き込まれていないかを突き合わせる。
生成 API は成功を返しながら壊れたファイルを寄こすので、**自己申告を信用しない**。

## Consequences

- **企画側の純粋関数性が守られる。** 非決定性と課金は生成スキルの中だけに閉じる。
  評価も企画側だけなら従来どおり再現する。
- **媒体とサービスを差し替えられる。** 企画側を別のスキルにすれば別媒体に、
  アダプタを差し替えれば別サービスに応用でき、**ハーネスの型は書き換わらない**。
- **ADR-0009 の「実体を生成しない」は、`produce-video` に限定された決定になった。**
  ハーネス全体としては実体を生成する。本 ADR が ADR-0009 の適用範囲を狭める。
- **工程が1つ増え、人間ゲートも増える**（課金の承認、作り直しの承認）。
  金が動く工程で自動的に作り直すわけにいかないため、これは避けられない。
- **アダプタの品質はハーネスが保証できない。** 契約を定めるだけで、
  ホストが契約を破っても検出できるのは `media-checker` の観測範囲に限られる。

## 却下した選択肢

- **produce-video に生成を足す**: スキルが1つで済む。しかし**企画側まで非決定になり**、
  外部サービス・課金・失敗リトライが企画の評価に混ざる。
  実際、企画側の評価が再現することは今回の開発で何度も助けになった。これを失うのは高い。
- **生成もホストに全部置く**（ハーネスは何も持たない）: 依存は完全に閉じる。しかし
  工程の順序・再計時の作法・検証の規律といった**媒体非依存の知識が、ホストごとに書き直される**。
  それは harness の存在理由（型を1箇所に置く）を捨てることである。
- **アダプタもハーネスに置く**（参考実装として）: すぐ使える。しかし CLAUDE.md §0
  「共有ハーネスは汎用のものだけを持つ」に反し、動画を作らないプロジェクトに
  ElevenLabs 依存を持ち込む。
- **検証を置かず、アダプタの報告を信じる**: 工程が減る。しかし生成 API は成功を返しながら
  壊れたファイルを寄こす。しかも**課金済みなので、気づくのが遅いほど高くつく**。
