# ADR-0014 調査の止め時を尺から逆算する。不足しても自動で回し直さない

## Context

[ADR-0012](ADR-0012-research-stage-confined-and-independently-verified.md) で調査工程を足したとき、
**「どこまで調べたら一旦区切りか」を定義しなかった**。`researcher` が持っていた契約は
`research.md` の書式（`F-nnn`・確度3段階・出典）だけで、件数も探索範囲も打ち切り条件も無い。

さらに skill が `researcher` に渡していたのは**テーマだけ**で、`brief.yaml` を渡していなかった。
つまり `researcher` は `duration_sec` も `points:` も見ておらず、
**必要量を逆算する材料をそもそも持っていなかった**。止め時が定義できないのではなく、定義しようがなかった。

放置すると3つ壊れる。

- **採取量が回ごとにブレる。** ADR-0012 は「非決定性を調査1工程に閉じ込める」と主張したが、
  閉じ込めた中身が無制限なら、採取量の分散がそのまま台本の分散になる。
  境界をファイルで切っただけでは閉じ込めたことにならず、**量を定めて初めて閉じる**。
- **`fact-checker` の後で足りなくなる。** 検証者は必ず何本か落とす・格下げする。
  台本が要る数ちょうどを集めていると、検証後に不足が判明し、
  人間ゲートまで進んでから調査工程へ戻ることになる。
- **「辿れなかったもの」を書く欄はあるのに、何ホップで諦めてよいかが無い。**
  1つの主張を無限に追うか1回で諦めるかが回ごとに変わり、
  深追いした回は**残りの主張が薄いまま `research.md` が完成する**。

## Decision

**必要量（下限）は尺から逆算し、探索の打ち切り（上限）は craft が持つ。不足しても自動で回し直さない。**

- **下限は `brief.yaml` の `duration_sec` から2段で導く**（式の SSOT は `rules/produce-video/research-format.md`）。
  「台本で使う事実」を尺から出し、**`fact-checker` が落とす分の余剰として×2する**。
  検証で目減りする前提で採るほうが、後から戻るより安い。
- **`⚠要確認` は0本と数える。** 採否が人間である以上、台本の頭数にならない。
- **skill は `researcher` に `brief.yaml` のパスを渡す。** これが無いと上の逆算が成立しない。
- **上限（1つの主張をどこまで追うか）は `researcher` の craft に置く。**
  一次情報へは2ホップまで、`確実` は独立2出典で打ち止め（3つ目を探さない）、目標本数に達したら止める。
- **本数が揃っても角度が1つなら足りていない。** 全部語源・全部数字といった偏りは、
  本数を増やすのではなく**欠けた角度を1本だけ**探して埋める。
- **目標は下限であって、確度と引き換えにしてよいノルマではない。**
  届かないまま打ち切り条件に達したなら、**確度を上げずに、届かないまま返す**。
- **不足を理由に orchestrator が `researcher` を回し直さない。** 人間ゲートで不足を明示し、
  再調査の可否は人間が決める。

## Consequences

- 同じテーマの採取量が尺で決まるようになり、調査工程の分散が縮む。ADR-0012 の閉じ込めが量の面でも閉じる。
- 検証後の目減りを見込んで採るので、`fact-checker` を通した後に台本が痩せにくい。
- 深追いで他の主張が薄くなる崩れ方が止まる。取りこぼしは「辿れなかったもの」に残り、人間には見える。
- **式は経験則であり、テーマの事実密度を反映しない。** 尺が同じでも、事実が薄い領域と濃い領域で必要量は違う。
- **×2 の余剰は `fact-checker` の落とし率の推定であって実測ではない。** 落とし率の高い領域では依然足りない。
- **本数という数値目標は、それ自体が水増しの圧力になる。** 文言で禁じているが、
  **機械では検出できない**（`確実` の水増しは `produce-video check` にかからない）。
  この設計は「水増しさせない仕組み」ではなく「水増しの動機を増やさない配置」までしか保証しない。

## 却下した選択肢

- **止め時を定めないまま（現状維持）**: 実装ゼロだが、上の3つの壊れ方をそのまま抱える。
  とくに「非決定性を1工程に閉じ込めた」という ADR-0012 の主張が量の面で成立していない。
- **固定本数を format ごとに置く**（short は8〜10本、と `short/direction.md` に数値で書く）:
  式が要らず単純。しかし format を増やすたびに追記が要り、同じ short でも15秒と60秒で必要量が違うことに追従しない。
  尺は既に `brief.yaml` にある入力なので、逆算のほうが依存が少ない。
- **本数を決めず、探索ルートの網羅だけで区切る**: 数値目標が無いので水増しの圧力は生まれない。
  しかし「ルートを尽くした」の判定が主観であり、回ごとのブレが残る。閉じ込めが完成しない。
- **不足時に orchestrator が自動で `researcher` を回し直す**: 一見親切だが、
  目標本数がノルマ化し「あと2本」の圧力が確度の水増しへ直結する。
  しかも調査工程は非決定的なので、回し直しは同じテーマで別の結果を返し、
  **何巡目を採るかの基準が無い**。人間ゲートは既に在るので、そこへ出すほうが安い。
- **目標本数を機械検査（`produce-video check`）で強制する**: 決定的に落とせる点は魅力的だが、
  機械が数えられるのは**行数であって確度の妥当性ではない**。本数を満たす最も安い方法が水増しである以上、
  機械強制は水増しを促す方向に働く。機械が撃ってよいのは `F-nnn` の参照切れのような、
  正解が一意に決まるものに限る。
