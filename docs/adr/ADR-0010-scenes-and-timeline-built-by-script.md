# ADR-0010 sonagi の L2 コマ定義と L3 タイムラインは、エージェントではなくスクリプトが決定的に組む

## Context

`sonagi` の L2（`scenes.json`）と L3（`timeline.json`）は、台本の行と各シーンの素材から導かれる。
中身は **開始秒の累積和・素材IDの解決・台本行との1対1の対応・合計尺**であり、
これらは前段の成果物から一意に定まる。

一方で、この2つが正しいことがスキルの価値の中核でもある。
「台本の各行が `scenes.json` のコマに1対1で対応している」「合計尺が指定尺に収まっている」は、
利用者が最初に確かめたい性質である。

## Decision

**`tools/sonagi build` が `script.md` と `assets/*.json` から機械的に生成する。**
オーケストレータもサブエージェントも、この2ファイルを手で書かない。

`layout` / `transition` などの演出意図は `asset-generator` がシーン単位で出し、
スクリプトはそれを**結合するだけ**にする。時間軸の計算に LLM を関与させない。

これにより、1対1の対応と合計尺は「検査して確かめる性質」ではなく**構造上必ず成り立つ性質**になる。
`build` は ERROR がある間は何も書かない（壊れた入力から導出物を作ると、原因が導出物側に散らばって追えなくなる）。

## Consequences

- 累積秒の計算ミス・行の取りこぼしという、LLM が確率的に起こす種類の誤りが原理的に消える。
- テストの assertion がスクリプトを叩くだけになり、評価が安く・再現する。
- `scenes.json` / `timeline.json` を人が手で直しても、次の `build` で上書きされる。
  **これらは導出物であり、直すべきは上流（台本か素材）である**という規律を強制する。
- 映像表現の自由度が `asset-generator` が出せる語彙の範囲に閉じる。
  スクリプトは「もっと凝った繋ぎ」を発明できない。

## 却下した選択肢

- **オーケストレータが組む**: 当初案。前段の成果物を全部見ている主体が組むのは自然に見えるが、
  LLM に JSON を手書きさせることになり、累積秒の計算ミスと行の取りこぼしが確率的に起きる。
  lint で拾えはするが、拾って直すループが毎回入る。
- **composer エージェントを立てる**: レイアウトとトランジションの選択を演出判断とみなし、専任に任せる案。
  表現の幅は上がるが、**時間軸の正しさが再び LLM 依存に戻る**。
  演出の幅は `asset-generator` がシーンごとに意図を出す形でも足り、そちらは1シーンに閉じるので検査もしやすい。
- **スクリプトが素材の中身まで決める**（レイアウトを役割から機械的に導く）: 完全に決定的になるが、
  全動画が同じ見た目になる。演出の判断は残す価値がある。
