# ADR-0017 面白さは comedian が発散し人間が収束させる。台本より前に構成のゲートを置く

## Context

実運用の1本目（雑学チャンネル）を通した結果、**成立はしているが面白くない**動画定義が出た。
事実は正確で、出典は検証済みで、尺も語彙も検査を通っていた。それでも見る理由が無かった。

原因を辿ると、**チャンネルの約束を担当するエージェントが1人もいなかった**。
`channel/identity.md` は「人に話せるネタを1つ」「明日それを誰かに言いたくなるかが合否」と定めているが、
各エージェントの仕事は researcher＝事実を集める、script-writer＝尺の配分とフックの位置、
asset-generator＝1コマ1メッセージ、judge＝ブレと矛盾の摘発である。
**全員が「悪さを防ぐ」係で、「良さを作る」係がいない。**

構造的な帰結も出た。9シーン中4シーン28秒——動画の半分——が「別の人がこう言っている」に費やされた。
`research.md` の**証拠の構造をそのままシーンに写した**結果であり、
確度の規律（正しい）が構成にまで漏れた形である。視聴者は誰が言ったかに興味がない。

そして面白さは**機械が判定できない**。judge を増やしても、lint を足しても作れない。

## Decision

**面白さを作る工程を1つ立て、判断を人間に、発散と実行を AI に割る。**

- **`comedian`（新エージェント）が発散する。** `research.md` から**構造的に違う構成案を3つ**出す。
  各案は「へえの一点／使う型／明かす順／**捨てる事実**／滑る条件」を持つ。
  題材が弱ければ「この回はやめる」も選択肢として出す。
- **🙋 人間が収束する。** 3案から選ぶ・混ぜる・却下する。承認は `angle.md` の `status: chosen`。
  **人間の仕事は「書く」ではなく「選ぶ」**なので、1本あたり数分で済み、本数が回る。
- **AI が実行する。** `script-writer` 以降は選ばれた案から外れない。
  「捨てる事実」に挙がった `F-nnn` を登場させてはならない。

**craft は笑いの技術に置く。** このチャンネルが狙うのは笑いではなく「へえ」だが、
エンジンは同じ（予測の裏切り）であり、笑いの技術は経験則ではなく**型**なので再現できる。
agent body は、緊張と緩和・フリとオチ・共感・具体・落差・天丼・出し惜しみ・立場を下げる・視点の移動を、
**「何が要るか」と「どう滑るか」の対**で持つ。型を知っているだけの者は滑る条件を知らないので滑る。
併せて**型ごとの必要尺**を持たせる（天丼は15秒以上、共感は3秒）。

**味気なさの一部は機械で撃つ。** 良いものは作れないが、同一性は検出できる。
`produce-video check` に C18（カメラの角度が1種類に偏っていないか）を足した。

**「出典の提示に使ってよいのは1シーンまで」を規則にする。** 証拠の並置は視聴者にとって
情報ではなく確認作業であり、その秒数は「へえ」に使うべきものである。

## Consequences

- 面白さの決定権が完全に人間側に来る。AI は選択肢を作る係になり、責任の所在が明確になる。
- 人間ゲートが1枚増える（構成／台本の2枚）。ただし台本ゲートは設計が済んでいるぶん速くなる。
- **弱い題材を捨てられるようになった。** 調査コストは戻らないが、その先のコストは払わずに済む。
- **型の機械的な適用という新しい失敗様式が生まれる。** 「ここで天丼を入れました」という
  技術の披露は、面白さではない。agent body は滑る条件を並べてこれに抗っているが、防ぎ切れる保証はない。
- **面白さの上限は依然として確度が決める。** 言い切れない事実を核にした案は、
  台本で「〜と言われています」としか言えず、フリとオチが成立しない。仕組みでは解けない。
- C18 は WARN であり、意図して同じ角度を続ける演出を否定しない。判断は人間に残る。

## 却下した選択肢

- **judge に「面白いか」も判定させる**: エージェントを増やさずに済む。しかし
  **judge は反証のオラクルであり、無いものを作れない**。「面白くない」と言えても
  「こうすれば面白い」は言えず、しかも判定が主観なので反証の形にならない。
  さらに judge は素材が全部できてから走るので、**指摘が最も高くつく地点**で出る。
- **script-writer に面白さの craft を足す**: 新しいエージェントが要らない。しかし
  script-writer は既に尺の配分・表記・確度を背負っており、**面白さは常にそれらに負ける**
  （制約を満たすほうが確実に採点されるため）。役割を混ぜると、弱いほうが捨てられる。
- **人間が構成を白紙から書く**: 面白さは最大化される。しかし**本数が回らない**——
  この仕組みの存在理由は量であり、1本ごとに人間が構成を書くなら仕組みは要らない。
- **AI に全部任せて、人間は最後に見るだけ**: 最も安い。しかし実際にそれをやった結果が
  「証拠を順番に並べただけの動画」であり、この ADR はその結果から書かれている。
