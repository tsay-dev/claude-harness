# ADR-0018 多言語はマスターのタイムラインを固定し、定義側の翻訳と実測フィットで作る

## Context

動画を多言語（マスター言語＋複数言語）で配信したい。配信先の主要な形態は
**1本の動画に複数の音声トラックと字幕を載せ、視聴者の言語で再生する**ものであり、
この形態は「映像は1本・コマ割りは全言語で共通」を構造的に要求する。

コスト構造も同じ向きを向いている。実体化の原価の9割超は動画クリップと画像が占め、
これらは（画像への文字焼き込みを検査で禁じている結果）**言語中立**である。
言語に依存するのはナレーション・caption / telop・公開メタデータだけで、
1言語追加の限界費用は TTS 数セントに落ちる——**映像を言語ごとに作った瞬間にこの構造は消える**。

一方で時間軸に本質的な制約がある。コマ割りはマスター言語の音声の実測
（[ADR-0015](ADR-0015-split-planning-and-rendering.md) の retime）で決まるが、
同じ内容を別の言語で話すと尺は変わる。全言語を1本の映像に載せるなら、
**どこかの言語を基準に固定し、他の言語をそこへ収める**しかない。

## Decision

**マスター言語のタイムラインを唯一の時間軸として固定し、翻訳をそこへ収める。**

- **再計時はマスター言語で1度だけ**行い、翻訳音声は言語ごとに再計時しない
  （rules/render-media/retime.md）。マスターでは「音に画を合わせ」、翻訳では「マスターの窓に音を合わせる」。
- **翻訳は定義側（produce-video）の成果物**とする。`brief.yaml` の `languages:` が指定された回に、
  localizer（1言語1体・言語内は1脳）が `i18n/<lang>.json` を書き、
  翻訳を書いていない localization-judge が反証する（作る主体≠判定する主体）。
- **訳文はシーン尺 × その言語の実測話速の文字予算に収める**。予算は機械検査（C19/C20）が守り、
  超過だけを ERROR とする（窓に入らない）。短い側は間になるので許す。
  話速は言語ごとに `calibrate --lang` で実測してから訳す（推測の話速を禁じる）。
- **収まりの最終権威はレンダリング時の実測**とする。アダプタは `audio --lang` で生成した音声を実測し、
  窓に収まらないシーンを**速度で押し込まずに**翻訳側の欠陥として報告する。
- 字幕（`srt --lang`）と言語別完成音声（`compose --lang`）はアダプタの契約に足す。
  **映像に焼く文字をどの言語にするかは決めない**——それはチャンネル／ホストの方針である。
  音声トラック・字幕・言語別メタデータの配信先への登録は人間の手作業として引き渡しに明示する。

## Consequences

- 良: 1言語追加の限界費用が TTS ぶんだけになる（映像・画像・BGM・効果音は全言語で共有）。
- 良: 翻訳が定義側にあるので、実体化の前に機械検査と独立レビューが効く（企画側は純粋関数のまま）。
- 悪: 訳文がマスターの間合いに縛られ、文字予算のために**情報を削る翻訳**を強いられるシーンが出る。
  直訳の完全性より要点の保持を優先する規律を localizer に負わせた。
- 悪: 言語ごとに話速の実測（較正）が先に要り、声がその言語を話せるかは鳴らすまで分からない。
  話せない場合の代替（言語だけ別の声・配信先の自動吹き替え）はチャンネル側の判断として残る。
- 悪: 複数音声トラックの登録に API を持たない配信先があり、公開作業の一部が手作業に残る。

## 却下した選択肢

- **言語ごとに映像を作る（言語別の再計時と結合）**: 尺の自由度は最大になるが、原価の9割超を占める
  動画クリップが言語数ぶん膨らみ、1本の動画に音声トラックを載せる配信形態にも乗らない。
  言語別アカウント運用が要る配信先では、マスターの完成物をそのまま流用すれば足りる。
- **翻訳をレンダリング側（render-media）の工程にする**: 生成の直前に訳せば実測の窓に直接合わせられるが、
  翻訳は検査・レビュー・再現が要る定義の仕事であり、非決定性の側に混ぜると企画側の純粋関数性
  （ADR-0015 の分割の理由）が崩れる。
- **配信先の自動吹き替えだけに任せる**: パイプライン変更ゼロで最低線としては常に残るが、
  品質・対応言語・字幕と画面文字の整合をプラットフォームに委ねることになり、
  「見るユーザーに合わせて適切な音声とキャプションを入れる」という目的そのものを機構として持てない。
