# 🎬 render-media — 定義を実体にする指揮者（orchestrator）

> **このスキルを起動した時点で、あなた（メインエージェント）は中立の orchestrator である。**
> あなたは生成しない・判定しない。**ホストのアダプタ（`tools/render/`）を工程順に叩き、
> 生成物を検証する `media-checker` を別コンテキストで起動する指揮者**に徹する。
> 型（なぜ・何を・書式）の SSOT は rules（`.claude/rules/render-media/`）。
> **サービス固有の事情は知らない**——どのサービスをどう叩くかはアダプタの中にある。

## 🔒 このスキルが踏み越えない線

- **定義を書き換えない。** `script.md` / `scenes.json` / `timeline.json` / `assets/*.json` は読み取り専用。
  実測が定義とずれても、**定義は定義のまま残す**（それは予測であって実測ではない）。
- **サービスを直接叩かない。** エンドポイントもモデルIDも知らない。アダプタの契約だけを知る。
- **在るものを作り直さない。** 課金が発生するので、これは規律ではなく実害の回避である。
- **秘密に触らない。** キーを読まない・書かない・会話や成果物に写さない。
  供給はホストの仕事であり、あなたが知るのは `preflight` の成否だけである。
- **オーケストレータは生成しない。** アダプタを叩き、実測を突き合わせ、分岐する。

## 起動時に確定させる入力

- **対象動画のディレクトリ**（`scenes.json` と `assets/` を持つ場所）
- **アダプタの場所**（既定は `<host>/tools/render/`）。無ければ**そこで止まる**——
  アダプタはホストの持ち物であり、このスキルが書くものではない（🙋 人間ゲート）
- **鍵と設定が揃っているか**（`preflight`）。**どのキーが要るかを、あなたは知らない**——
  知っているのはアダプタであり、あなたは叩いて結果を受け取るだけである
- **課金の了解。** 生成には金がかかる。**規模（何枚・何本・何言語・概算）を先に提示し、承認を得る**（🙋）

## 🧑‍⚖️ 生成する主体と検証する主体を分ける

生成したアダプタは「作った」としか言えない。**要求どおりのものを得たかは実体を見ないと分からない。**
そして生成 API は成功を返しながら壊れたファイルを寄こす。**200 は「作れた」ではない。**

| 役割 | 実体 | 担当 |
| --- | --- | --- |
| **orchestrator（中立）** | このスキルを起動したあなた（インライン） | 入力確定・アダプタ起動・分岐・引き渡し |
| **アダプタ** | ホストの `tools/render/`（このスキルの外） | サービスを叩いて `media/` にファイルを置く |
| **media-checker** | [`agents/render-media/media-checker.md`](../../agents/render-media/media-checker.md) | 実体を開いて要求と突き合わせる。**生成していない別コンテキスト必須** |

## 実行台本（orchestrator の回し方）

段階＝ファイル成果物。**在れば済み、無ければ未了**であり、途中から再実行できる。

1. **入力確定と preflight（インライン）。** 対象・アダプタ・規模を固め、
   **`<adapter> <dir> preflight` を叩いてから課金の承認を取る**（🙋）。
   preflight は何も生成せず課金しない。**順序を逆にしない**——工程は画像から走るので、
   音声のキーが無いことは音声工程まで分からず、**画像を課金した後に止まる**。
   足りないものが報告されたら、**そこで止めて人間へ返す**（キーの供給はホストの仕事で、あなたは触らない）。

2. **画像。** `<adapter> <dir> images`。動画クリップの開始フレームに使うので、動画より先。

3. **音声。** `<adapter> <dir> audio`。**尺の実測値がここで初めて手に入る。**

4. **再計時。** `<adapter> <dir> retime`。実測タイムライン `media/timeline.actual.json` が出る。
   **音に画を合わせる**（型の SSOT は `rules/render-media/retime.md`）。
   **1コマのずれが 2 秒を超えたら、台本側の問題として人間へ報告する**（🙋）。実測で押し通さない。

5. **翻訳音声と字幕（`i18n/` が在るときだけ）。** 言語ごとに `<adapter> <dir> audio --lang <code>`、
   全言語ぶん `<adapter> <dir> srt --lang <code>`（マスター言語の SRT も出す。srt は課金ゼロ）。
   **再計時の後**に置くのは、翻訳音声が収まるべき「窓」がマスターの実測で初めて確定するからである
   （型の SSOT は `rules/render-media/retime.md`）。窓に**収まらないシーンが報告されたら、
   それは翻訳（定義）側の欠陥**である——実測で押し通さず、該当言語・該当シーンの訳の直しとして
   人間へ返す（🙋 直しは produce-video の多言語化工程の差し戻しであり、このスキルは定義を書き換えない）。

6. **効果音・BGM。** `<adapter> <dir> sfx` / `bgm`。BGM の長さは総尺に依存するので、再計時の後。

7. **動画クリップ。** `<adapter> <dir> video`。**実測尺**で作る。
   サービスの制約（クリップ長が離散値、上限がある）はアダプタが吸収するが、
   **吸収できないもの**（上限を超える長さが要る等）は報告されるので、**人間に選ばせる**（🙋）。

8. **media-checker を Task 起動（別コンテキスト必須）。** 渡すのはパスだけ。
   実体を開いて、長さ・寸法・比率・**画像に文字が焼き込まれていないか**・
   **翻訳音声が各シーンの窓に収まっているか**を突き合わせる。

9. **分岐。** 作り直すべきものは、**そのファイルを消して**該当工程を `--only` で回す。
   **課金が発生するので、作り直しは人間の承認を取る**（🙋）。

10. **結合。** `<adapter> <dir> compose`。実測タイムラインどおりに重ねる。
    多言語の回は言語ごとに `compose --lang <code>` で完成音声 `final.audio.<lang>.mp3` も出す。

11. **引き渡し。** 成果物と、人間の仕事を明示する。多言語の回は、
    **音声トラック・字幕・言語別メタデータのプラットフォームへの登録が人間の手作業**であることを明示する
    （複数音声トラックの登録に API を持たない配信先がある）。

## 出力（すべて `<video_dir>/media/`）

| ファイル | 内容 |
| --- | --- |
| `<scene_id>.png` | コマの静止画 |
| `<scene_id>.mp3` | ナレーション |
| `<scene_id>.sfx.mp3` | 効果音（`sfx: none` のコマには無い） |
| `bgm.mp3` | BGM |
| `<scene_id>.mp4` | 動画クリップ |
| `timeline.actual.json` | **実測**タイムライン（定義とは別物として残す。マスター言語で1度だけ） |
| `<lang>/<scene_id>.mp3` | 翻訳ナレーション（`i18n/` があるときだけ） |
| `<lang>.srt` | 言語別の字幕（マスター言語ぶんも出す） |
| `final.audio.<lang>.mp3` | 言語別の完成音声（音声トラックとして登録する実体） |
| `media-review.md` | 生成物の検証結果 |
| `final.mp4` | 結合済みの完成物 |

## 引き渡し（何が済み・何が人間の仕事か）

- ✅ 済: 素材の生成・実測での再計時・**独立した検証**・結合
- ⏳ 人間: `media-review.md` の指摘への判断（作り直すかどうか＝課金の判断）、公開、
  （多言語の回は）音声トラック・字幕・言語別メタデータの配信先への登録
- **AI 出力は必ず人間チェックを通す前提。**

## ✅ 着手前チェックリスト

- [ ] アダプタがホストに在るか（無ければ止まる。このスキルは書かない）
- [ ] **`preflight` を叩いてから課金の承認を得たか**（承認の後に preflight を回していないか）
- [ ] **課金の規模を提示して承認を得たか**
- [ ] 工程の順序を守ったか（画像 → 音声 → **再計時** → 翻訳音声/字幕 → 効果音/BGM → 動画 → 結合）
- [ ] 再計時を飛ばしていないか（飛ばすと予測の尺で動画クリップを作ることになる）
- [ ] 翻訳音声を**マスターの実測タイムラインより先に**作っていないか（窓が確定する前に作ると収まりを検証できない）
- [ ] 窓に収まらない翻訳音声を、速度を変えて押し込んでいないか（それは翻訳側の欠陥として人間へ返す）
- [ ] 生成物を**実測してから**完了と言ったか（API の 200 を信用していないか）
- [ ] 検証を**生成していない別コンテキスト（media-checker）**で回したか
- [ ] 作り直しの前に承認を取ったか
