# 📦 アダプタの契約（サービス固有の実装が満たすもの）

> この型はサービスを知らない。知っているのは**アダプタが満たすべき契約**だけである。
> なぜ分けるかは [overview.md](overview.md)。
> 実行手続きは skill [render-media](../../skills/render-media/SKILL.md)。

## アダプタはホストが持つ

**共有ハーネスにサービス固有の実装を置かない。** ElevenLabs でも Stable Diffusion でも、
それは「そのプロジェクトの都合」であって、動画を作らないプロジェクトに依存を持ち込む理由はない。

ハーネスは契約を定め、**ホストが `tools/render/` に実装を置く**。
サービスを乗り換えるとき、書き換わるのはホスト側だけである。

## 🔒 契約

アダプタは**サブコマンドを持つ1つの実行可能ファイル**である。

```
<adapter> <video_dir> images   [--only SC-03 ...]
<adapter> <video_dir> audio    [--only ...]
<adapter> <video_dir> retime
<adapter> <video_dir> sfx      [--only ...]
<adapter> <video_dir> bgm
<adapter> <video_dir> video    [--only ...]
<adapter> <video_dir> compose
<adapter> <video_dir> all
```

### 守ること

- **出力は `<video_dir>/media/` 配下の固定名だけ。** それ以外の場所に書かない
  （`<scene_id>.png` / `<scene_id>.mp3` / `<scene_id>.sfx.mp3` / `<scene_id>.mp4` / `bgm.mp3` / `final.mp4`）
- **在るファイルは作り直さない。** 課金が発生するので、これは実害の回避である
- **`--only` で対象を絞れる。** 1つだけ作り直したいときに全部を回さないため
- **定義を書き換えない。** `script.md` / `scenes.json` / `timeline.json` は読み取り専用
- **生成したものを実測してから報告する。** 長さ・サイズ・寸法。API の 200 は「作れた」ではない
- **サービスの制約は、アダプタが吸収する。** 例: クリップ長が離散値しか取れないなら、
  大きい側で作って切り詰める。**その事情を型の側に漏らさない**

### 報告すること

各工程の最後に、**何を作り、何を飛ばし、実測がいくつだったか**を出す。
飛ばしたものは「すでに在る」と明示する（黙って飛ばすと、作られたのかどうかが分からない）。

## サービスの制約は必ずある（吸収の例）

実際に当たったもの:

- **画像 API にネガティブプロンプトが無い。** 定義の `image.negative` を、
  正のプロンプトへ文章として畳み込む
- **動画のクリップ長が離散値**（4 / 6 / 8 秒しか受けない）。
  必要な長さ以上の値で作って切り詰める。**引き伸ばさない**（絵が破綻する）
- **上限を超える長さが要る**とき。切り詰めでは解決しないので、
  複数クリップを繋ぐか、静止画を継ぎ足すか、そのコマだけ静止画にするかを**人間に選ばせる**

**アダプタが黙って劣化させない。** 尺が足りない・比率が違う・ネガティブが効かないといった
「望んだものが作れなかった」場合、**それを報告する**。黙って近いもので埋めると、
出来上がってから気づくことになる。
