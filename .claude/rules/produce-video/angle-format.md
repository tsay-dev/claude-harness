# 📦 構成案の書式（angle.md）

> 調べた事実の山から「この回の形」を決める工程の書式。
> なぜ人間がここに入るかは [overview.md](overview.md)。事実の書式は [research-format.md](research-format.md)。
> 実行手続きは skill [produce-video](../../skills/produce-video/SKILL.md)。

## この工程が背負っているもの

**面白さを作る唯一の工程である。** 他の工程は全て「悪さを防ぐ」係で、
事実を捏造しない・尺を外さない・断定しすぎないことしか見ていない。
それだけで作ると、動画は**調べた出典を順番に並べただけのもの**になる。

このチャンネルが狙うのは笑いではなく「へえ」だが、**エンジンは同じ**である——
どちらも予測の裏切りで動く。だから**笑いの技術（型）がそのまま使える**。
型は経験則ではないので再現でき、だから工程にできる。型の中身は agent body が SSOT。

そして**面白さは機械が判定できない。** だからここは、
**AI が案を出し（発散）、人間が選ぶ（収束）**という形にする。
人間の仕事は「書く」ことではなく「選ぶ」ことなので、本数を回せる。

**選ばれた案は `angle.md` に固定され、以降の工程はそこから外れない。**

## 🔒 3案は構造的に違えること

**同じ「へえ」の言い換えを3つ並べたものは、3案ではなく1案である。**
最低限、**核に据える `F-nnn` が3案で違う**こと。人間が選べない案の並べ方は、この工程の失敗である。

## 🔒 捨てる事実を明記すること

**「使わない `F-nnn`」を書いていない案は不完全である。**
捨てると書かれていない事実は台本に紛れ込み、動画は出典の一覧に戻る。

**出典の提示に使ってよいのは1シーンまで。** 「Aもこう言っている、Bもこう言っている」の並置は、
視聴者にとって情報ではなく確認作業であり、その秒数は「へえ」に使うべきものである。

## `angle.md`（angle-finder が書き、人間が選ぶ）

```markdown
---
video_id: <id>
status: proposed        # proposed | chosen
chosen: A               # 人間が選んだ案。status: chosen のときだけ書く
---

## 案A <この回を1文で>

- **へえの一点**: <持ち帰らせるもの1つ>（F-07）
- **使う型**: <緊張と緩和 / フリとオチ / 共感 / 具体 / 落差 / 天丼 / 出し惜しみ / 立場を下げる / 視点の移動>
- **型が要求するもの**: <その型が成立する条件を、この案でどう満たすか>
- **滑る条件**: <この案がどう外れうるか。型ごとの失敗様式に照らして>
- **なぜ明日話したくなるか**: <1行>
- **明かす順**: <結論から / 引っ張る / 問いを立てる>
- **入口**: <通説 / 数字 / 場面 / 視聴者の経験>
- **使う事実**: F-07, F-09
- **捨てる事実**: F-01, F-03, F-05, ...（**必須**）
- **前提の説明に使う秒数**: <見積もり>
- **賭けているもの**: <この案が当たる条件／外れる条件>
- **確度の制約**: <核の確度と、それが言い方に与える制限>

## 案B …
## 案C …

## この回はやめる（該当するときだけ）

- **理由**: <確度が届かない / 意外性がない / 尺に入らない>
- **代わりの候補**: <調査中に見つかった、より強い題材>
```

**人間が承認するときは `status: chosen` と `chosen:` を書き込む。**
案を混ぜたり書き換えたりしてよい——このファイルは人間が編集する前提の場所である。

## 台本との接続

`script-writer` は `angle.md` の**選ばれた案だけ**を見る。
「捨てる事実」に挙がった `F-nnn` を台本に登場させてはならない。

`status: chosen` でない `angle.md` は未承認であり、台本を書いてはならない。
