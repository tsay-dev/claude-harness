# 📦 全体像・思想（企画 → 公開パッケージ の階層モデル）

> 動画制作を **L0→L4 の一方向の派生**として型に落とし、各層の成果物をファイルとして固定する。
> ここは**この型の不変の核**（最初に読む）。書式の詳細は [schema.md](schema.md) / [channel-format.md](channel-format.md)、
> ショートの演出方針は [short/direction.md](short/direction.md)。
> 実行手続きは skill [sonagi](../../skills/sonagi/SKILL.md)。

## なぜ階層で切るか

動画を「1本の作品」として一息に作ると、**直したい箇所を直すために全部を作り直す**ことになる。
台本の1行を直したいだけなのに画像プロンプトも公開情報も巻き添えで消える。
層で切り、**各層を下の層から機械的に導けるようにする**と、変更の影響範囲が層の境界で止まる。

## 階層（この順にしか派生しない）

| 層 | 名前 | 実体 | 誰が作るか |
| --- | --- | --- | --- |
| **L0-** | 調査（任意） | `research.md`（出典付きの事実）＋ `research-review.md`（独立検証） | researcher / fact-checker |
| **L0** | 意図 | `brief.yaml`（企画・人間が与える）→ `script.md`（台本） | 人間 → script-writer |
| **L1** | 原子素材 | `assets/SC-nn.json`（キャプション・ナレーション・画像プロンプト・効果音・レイアウト意図）/ `assets/THUMB.json` | asset-generator / publisher |
| **L2** | コマ | `scenes.json`（素材ID群・開始秒・尺・レイアウト・出入りトランジション） | **スクリプト**（`tools/sonagi build`） |
| **L3** | タイムライン | `timeline.json`（コマの配列＋BGM＋解像度・fps・アスペクト） | **スクリプト**（同上） |
| **L4** | 公開パッケージ | `publish.md`（タイトル案3・説明文・タグ・チャプター）＋ `assets/THUMB.json` | publisher |

**サムネは時間軸を持たない特殊なコマ**である。`assets/THUMB.json` に L1 として置き、`scenes.json` の `thumbnail` キーへ畳み込まれる。

## 🔒 純粋関数的な契約（同じ入力 → 同じ出力構造）

副作用（ファイル出力）はあるが、**同じ入力に対して同じ出力構造を返す**ように以下を守る。

- **入力は `channel/` と `videos/<format>/<id>/brief.yaml` だけ。** それ以外の隠れた状態に依存しない。
- **外部サービスを叩かない。** 画像・音声・動画の**実体は生成しない**。出すのは**プロンプトと定義だけ**である。
  レンダリングは skill の外（人間または別ツール）の仕事。ここに手を出すと再現性も検証可能性も失われる。
- **事実を発明しない。** 台本に載せてよい事実は、**人間が `brief.yaml` の `points:` に書いたもの**か、
  **researcher が `research.md` に出典付きで置いたもの**だけである。
  台本より下流の工程は誰も調べない。埋められない箇所は `⚠要確認` を残して人間へ返す。
- **調査を入れるなら1工程に閉じ込める。** 外部を調べるのは researcher 1体だけとし、
  その出力 `research.md` は書き終わった瞬間に凍る。以降はこのファイルを固定入力として扱う。
  **調査工程だけは「同じ入力 → 同じ出力」が成り立たない**（web は変わる）。それを認めたうえで、
  非決定性がパイプライン全体へ漏れないように、境界をファイルで切る。
  そして事実は**集めた本人に検証させない**——出典を開き直すのは別コンテキストの fact-checker である。
- **`channel/` は読み取り専用。** 新しい語彙・口調・傾向を見つけても本体を書き換えず、
  `review.md` に**差分提案**として出す（承認・反映は人間＝skill 外）。
- **出力は固定パス・固定フォーマットだけ。** 隠しファイルや一時状態を置かない。

## 🔁 進捗は台帳ではなくファイルの存在で表す

別途の進捗台帳やステータスファイルを持たない（持つと必ず実体とずれる）。
**成果物ファイルが在れば済み、無ければ未了**である。だから途中から再実行できる。

- `assets/SC-nn.json` が在るシーンは**再生成しない**（人間が手で直した内容を巻き戻さないため）。
- 作り直したいシーンは、**そのファイルを消してから**再実行する。それが唯一の再生成の指示方法である。
- **捨てた理由は `assets/SC-nn.redo.md` に1行残す**（任意だが、強く勧める）。
  理由の無い削除は、作り直す側にとって当てずっぽうの引き直しでしかない。
  「画が他と浮いていた」のか「要点が運べていなかった」のかで直すべき場所は正反対であり、
  実際に、理由を伝えないまま作り直した結果**本編で一番効く主張が画面から消えた**ことがある。
  レビュアーも、改善なのか別方向への逸脱なのかを判定できなくなる。
  `.redo.md` は作り直しが済んだら消える（次の削除まで残さない）。
- `scenes.json` / `timeline.json` は **毎回スクリプトが作り直す**（下位から機械的に導ける導出物なので、手で守る価値がない）。

## 🧑‍⚖️ 作る主体と判定する主体を分ける

`asset-generator` はシーン単位で**並列に**走る。各シーンは互いを見ずに書くので、
**口調のブレ・用語のブレ・同じ言い回しの重複は構造的に必ず起きる**。書いた本人にはこれが見えない。
だから L1 完了後、素材を1つも書いていない `judge` が全シーンを横断して撃つ。

機械が反証できるもの（尺の合計・台本行とコマの1対1・閉じた語彙・参照切れ）は
`tools/sonagi check` が決定的に落とす。**LLM に算数をさせない。**
