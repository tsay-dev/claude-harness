# 📦 `channel/` の書式（チャンネル共通の「脳」）

> 回をまたいで一貫させるための共有知識。**読み取りが正**で、skill はここを書き換えない。
> なぜ共通化するかは [overview.md](overview.md)。
> 実行手続きは skill [sonagi](../../skills/sonagi/SKILL.md)。

## なぜ切り出すか

1本ごとに独立して作ると、口調・画風・タイトルの付け方が回ごとに揺れる。
視聴者はそれを「別のチャンネル」として受け取る。**単発の出来より、前回と同じであることのほうが効く。**
だから回を跨いで動かない部分をここに固定し、毎回の `brief.yaml` には**その回だけの差分**を書く。

## ファイル

### `identity.md` — チャンネルの人格

```markdown
# <チャンネル名>

## 誰に
<ターゲット。一人の具体的な人物として書く>

## 何を約束するか
<毎回必ず持ち帰らせるもの>

## 人格
<語り手のキャラクター。断定的か / 一緒に考えるか など>

## 禁止表現
- <使わない語・言い回し>
```

`禁止表現` は judge が機械的に突き合わせる欄である。**曖昧な方針ではなく、語そのものを列挙する。**

### `voice.md` — ナレーターの口調

```markdown
## 話速
6.5   # 文字/秒。尺予算の計算に使う唯一の数値

## 一人称・二人称
<「僕」「あなた」など>

## 語尾
- 標準: <〜です / 〜ですね>
- 避ける: <〜だぞ>

## 言い換え表
| 避ける | 使う |
| --- | --- |
| 〜させていただく | 〜します |
```

**話速はここにしかない。** `script.md` の frontmatter へ写して尺予算を計算する。
TTS を替えて体感速度が変わったら、直すのはこの1箇所だけである。

**この数値は推測で置かない。実際に読ませて測る**（`sonagi calibrate`）。
尺予算の全計算がこの1つの数値に乗っているので、外していると台本・素材・コマ定義が丸ごと作り直しになる。
実測すると推測から1割ずれることは珍しくない（推測 6.5 に対し実測 5.91 で、60秒の台本が 65.6 秒になった例がある）。
**TTS を替えたら測り直す。** 話速はその TTS の性質であって、チャンネルの性質ではない。

### `style.md` — ビジュアルスタイル語彙

**画風と禁止要素は「そのまま貼る英語の1文字列」として置く。** 日本語の散文で書いてはならない。

散文で「生成り」「濃紺」と書くと、シーンごとに並列で走る producer が**各自で英訳する**。
実際に `unbleached ecru` / `off-white` / `cream` / 欠落 の4通りに割れたことがある。
本人には自分の1シーンしか見えないので、割れていることに誰も気づかない。
**正規形をここに1つだけ置き、機械的にコピーさせる**のが唯一の解である（機械検査 C16 がこの一致を見る）。

````markdown
## image.style（この1行をそのまま貼る）

```
flat vector illustration, muted palette, thick outlines, no gradients
```

## image.negative（この1行をそのまま貼る）

```
text, logos, watermarks, human faces, brand marks
```

## 配色の意味（何色が何を指すか）
| 色 | 英語表記 | 意味 |
| --- | --- | --- |
| 濃紺 | deep navy | 地 |
| 生成り | unbleached ecru | 背景 |
| からし色 | mustard yellow | <この色が指すものを1つに決める> |

## フォント
<テロップ / キャプション>
````

見出しの直後のコードブロックが**正規文字列そのもの**である（機械がここを読む）。
書き換えるとその回から画風が変わるので、**変えるときは意図して変える**。

**固定したいキーを増やせる。** `## image.lighting（この1行をそのまま貼る）` のように見出しとコードブロックを足せば、
そのキーも全素材で一致が強制される（機械検査 C16）。逆に**宣言しなければ自由**である——
`lighting` を場面ごとに変えたいチャンネルもあるので、何を固定するかはチャンネルの裁量に置く。
（実際に、`lighting` を宣言していないチャンネルで1コマだけ `daylight` に浮いたことがある。
揃えたいなら宣言する、が答えである。）

**配色は意味を1つに固定する。** 「強調色＝間違い」と「強調色＝注目させたい正解」が同じ動画に混ざると、
視聴者は冒頭で覚えた意味のまま CTA を読み、逆の印象を持ち帰る。色は語彙であって装飾ではない。

### `history.md` — 過去タイトルの傾向

```markdown
| 日付 | タイトル | 型 |
| --- | --- | --- |
| 2026-08-01 | <タイトル> | 疑問形 |
```

publisher がタイトル案を出すときに参照し、**直近と同じ型・同じ言い回しを避ける**ために使う。

## `channel/` が無いとき

初回はブートストラップする。**勝手に本体を作らない**——`videos/<format>/<id>/channel-draft.md` に
`channel/` 各ファイルの草案を**提案として**出し、人間が承認して配置する。
承認前に走ると、後続の全ての回がその推測を踏襲してしまう。

草案は `review.md` ではなく専用のファイルに出す。`review.md` は judge が後段で書く場所であり、
同じファイルを使うと**承認前の草案が反証レビューに上書きされる**。
